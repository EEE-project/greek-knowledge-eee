- **Added the textbook as a second source to 12 existing rules and cross-linked one more** -- `accusative-objects-prepositions-time` (clock time and duration expressions), `areso-agreement` (**μου πάει**, **μου κάνει**), `definite-articles-nom-acc`, `future-tha-aspect` (more irregular future stems, future time markers), `genitive-possession` (age, dates, **Τίνος;**), `indefinite-article-enas`, `location-prepositions` (the place-adverb list, **προς**), `modern-neuter-noun-plurals` (the neuter -ος → -η pattern), `na-dependent-verb-forms`, `possessives-and-dikos` (the second accent on proparoxytone nouns), `preposition-me-instrument-and-company` (transport and payment phrases), and `conditional-type-1` (now also A2: the result clause may be an imperative) -- while `weak-pronouns-position` now links to the imperative rule instead of saying the topic is not covered.
- **Corrected the final -ν rule in `indefinite-article-enas` and stated it in `definite-articles-nom-acc`.** The published text described the Modern Greek **-ν** as the Ancient Greek movable ν -- kept before a vowel or a pause, dropped before a consonant -- without a source. It is now the standard Modern Greek rule: the masculine **τον/έναν/αυτόν** always keep their **-ν**, while the feminine **την** and **δεν/μην** keep it only before a vowel or **κ, π, τ, ξ, ψ, γκ, μπ, ντ**, cited to the Greek Wikipedia article «Τελικό νι», which itself cites the official school grammar.
- **`greek-knowledge check` no longer fails on a trailing newline.** It compared each file's body byte-for-byte with its canonical rendering, so a Literary Translation saved by an editor with a final newline was reported as "footnote-definitions block doesn't match sources" -- a misleading message for a difference that isn't content. Trailing newlines are now ignored in that comparison.

Now requires a `pos` column, not just `lemma`, before treating a TSV as vocabulary; `translation_presence.tsv` is explicitly skipped and logged quietly, not as a warning.
  - `collect_slot_forms()` was gap-filling every pronoun slot template against every plausible pronoun family (personal/demonstrative/relative/etc.) regardless of which family the lemma actually belongs to, burning real LLM requests on slots that can never apply to that lemma. Rewritten as a two-pass, family-aware lookup.
  - `pipeline.run()` used to re-attempt (and re-fail) every remaining candidate one-by-one after the gap-filler's `max_requests_per_run` budget was exhausted, and discarded the run's cache instead of preserving it. Now stops the run cleanly the moment the budget is hit, skips `grammar_rules`/`cultural_topics`/pruning (since the run never reached the rest of the course), and preserves the cache — verified twice, for real, that a small-budget run stops cleanly and a second real run against the same cache genuinely resumes instead of re-paying for already-resolved gaps.
  - `GapFillCache.make_key()` included the caller's `max_requests_per_run` in its cache key, meaning resuming an exhausted run with a *raised* budget (the whole point of that recovery path) silently invalidated every previously-cached gap instead of reusing it. Now normalizes the budget out of the key (memoized, since this ran on every `fill_gap()` call).
  - `RequestBudgetExceededError` (new, `okfbuild/sources/llm_gap_filler.py`) replaces a bare `RuntimeError` matched by exact message string for the budget-exceeded signal -- the old check would have silently stopped recognizing budget exhaustion the moment the message wording changed.
  - `NotLegalPronounException` (new, in the sibling `modern-greek-inflexion-eee` package -- see that package's own CHANGELOG, 2.1.10) replaces a bare `ValueError` that library used to raise for an Ancient-Greek-only pronoun (σύ, τίς, μιν, ὅδε, ...) run against the Modern Greek backend. `eee_engine.py`'s "not a modern Greek word" exception tuple now catches this by name instead of a broad, unrelated-bug-risking bare `ValueError`. This briefly meant a fresh `uv sync` installed a `modern-greek-inflexion-eee` without the new exception and `okfbuild.sources.eee_engine` failed to import -- flagged independently by an external Codex review of this same diff -- closed by bumping this repo's dependency floor to `>=2.1.10` once that release was actually live on PyPI.
  - README's Usage section rewritten with real, individually-verified-runnable examples (`SourceBundle` wiring, building one concept file, running the full pipeline over a course) and several gotchas found live while verifying them: `out_dir`'s pruning risk against this repo's own real content (`grammar/`/`culture/` files were accidentally marked `deprecated` once by an under-scoped example, reverted; the example now defaults to a scratch directory), `Path(...)` not expanding a leading `~` on its own, and what a healthy `report` actually looks like.

- **LLM gap-filler pipeline wiring** (5 sections, branch `feature/llm-gap-filler-pipeline-wiring`, not yet merged) — builds on the earlier `llm-backend-eee` foundation (`fill_gap()`/`GapFillCache`/`LLMModelConfig`, merged separately today) to make LLM-assisted morphology gap-filling actually usable end-to-end, from prompt context through a real pilot run to independent verification.
  - `fill_gap()` now receives a `context` string (the grammatical slot label, plus period/dialect/author/work when known) that reaches both the real LLM prompt — via `llm-backend-eee`'s own `label` mechanism, confirmed against its installed source — and the cache key, so a query under different context is never served from a differently-scoped cache hit. Course-level author/work/dialect metadata (curated in a new, deliberately small `okfbuild/course_context.py`, currently just the Odyssey and Kavafis Ithaki courses) is course-level signal ("this gap comes from the Odyssey course"), never conflated with word-level attestation ("Homer's own text uses this exact form").
  - `GapFillCache` gained `save()`/`load()`: atomic writes (temp file + `os.replace()`), a `format_version` field, exclusion of transient failures from persistence (an all-`CALL_FAILED` entry is never written as a stable negative result — it would wrongly block a legitimate retry), and run-ID-scoped resumability under a caller-supplied `gap_fill_cache_dir` (`<dir>/.gap_fill_runs/<run-id>/cache.json`). `pipeline.run()` shares one cache across every lemma it processes and automatically resumes the most recent incomplete run; a run that completes normally removes its own cache file.
  - A three-layer pytest gate protects any real, billed LLM API test from running by accident: a `paid_llm_api` marker, a `--run-paid-llm-tests` CLI flag (via a custom collection hook, not `addopts`, since `addopts` is trivially overridden by an explicit `-m` on the command line), and a fixture-level double-gate function (`require_paid_llm_gate()`) that re-checks a real API key plus `GREEK_KNOWLEDGE_RUN_PAID_LLM_TESTS=1` every time, regardless of how a test was invoked — the fixture-level check is the actual enforcement boundary, not the marker.
  - A real, two-model `GapFillerConfig` via OpenRouter (`openai/gpt-4o-mini` + `anthropic/claude-3.5-haiku`, one API key: `GREEK_KNOWLEDGE_OPENROUTER_API_KEY`) plus `okfbuild/gap_filler_pilot.py`'s `run_gap_filler_pilot()`: writes to an isolated, gitignored `build/gap-filler-pilot/` directory — never the tracked `words/`/`grammar`/`culture` trees, since an exploratory LLM-gap-filled run shouldn't land in already-reviewed output before a human sees it — plus a JSON "handoff" file recording every individual LLM-inferred form with full structured provenance (lemma/form/slot label/features/pos/language/period/method). Confirmed directly (OpenRouter's own API reference, plus the installed `llm-backend-eee` v0.2.1 source) that a routing provider can silently substitute a different model than requested, and that `llm-backend-eee` discards the response field that would reveal it — so the handoff's `method` field reflects the model *requested*, never confirmed as the one that actually responded. Documented, not fixed (would need a change in that separate package).
  - `okfbuild/morpheus_crosscheck.py`: a standalone tool cross-checking the handoff file's forms against the real Perseids Morpheus service, classifying each into `CONFIRMED` / `DIFFERENT_ANALYSIS` / `UNDERSPECIFIED` / `UNCONFIRMED` / `QUERY_FAILED` via a 7-axis UD-FEATS↔Morpheus vocabulary mapping built from real captured Morpheus responses (full, spelled-out English words like `"genitive"`) — not the abbreviated shape (`"gen"`) this repo's own pre-existing `MorpheusClient` test fixtures happen to use, which would have made the classifier look correct in tests while being silently wrong against every real response. Voice is modeled as match-sets, not a flat lookup: a `mediopassive` reading neither confirms nor contradicts a specifically-requested `Mid`/`Pass`. Purely informational — flags disagreement, blocks nothing, never modifies `words/*.md`.
