# Changelog

## 2026-09-03

- **LSJ is now genuinely functional end-to-end, closing the gap the earlier wiring-only pass left open** -- downloaded the real 27-file Perseus TEI-XML dump (~270MB) and made the "Ancient Greek meaning" section actually produce real content instead of always being empty.
  - Rearchitected `LSJIndex` to match `CachedWiktextractIndex`'s proven shape rather than repeat the exact problem that pattern was built to fix: a new `CachedLSJIndex` resolves and caches only the headwords a course actually looks up, as small per-headword JSON files under `data/lsj-cache/` (git-tracked, plain), instead of parsing all 27 files (~270MB) into memory on every process. The raw TEI-XML dump itself is a one-time, local-only, gitignored download to `data/lsj/` (matching `data/wiktextract/`'s pattern) -- `.gitattributes`' now-unneeded Git LFS tracking for it removed entirely.
  - **Discovered only once the real dump was parsed**: headwords and Greek body text in the real files are Beta Code (e.g. `key="no/stos"` for νόστος), not Unicode Greek -- the small hand-written test fixture predates this and uses real Greek characters directly, so nothing surfaced the gap until real data was actually downloaded. Converted via the `beta-code` PyPI package (perseids-tools, the same organization as Perseids Morpheus, already a dependency here). Conversion is element-aware, not whole-text: entries mix Beta Code Greek with plain English glosses and bibliographic abbreviations in the same entry, and naive whole-text conversion mangles the English (e.g. "good" -> "γοοδ") -- only text within a `lang="greek"`-tagged element (or its descendants) gets converted. Known, accepted limitation inherent to Beta Code itself, not fixed: a literal parenthesis used editorially inside a Greek span (e.g. a cross-reference like "(ne/omai)") is ambiguous with Beta Code's own breathing-mark notation and gets misconverted.
  - **Also discovered only against the real files**: their DOCTYPE declares 2 parameter entities -- `%TEI.XML "INCLUDE"` (genuinely internal) and `%PersDict PUBLIC ... "http://www.perseus.tufts.edu/DTD/1.0/PersDict.dtd"` (an *external* parameter entity, actually referenced via `%PersDict;`, confirmed directly against the real files) -- which `defusedxml`'s default policy (correctly) rejects, since it forbids all entity declarations unconditionally. Fixed with a custom `_LSJXMLParser` that narrows the check to general entities only (the ones a real attack payload would use, referenced from document content via `&name;`, never possible via a parameter entity's `%name;`, which is usable only within the DTD itself) -- verified to still correctly reject the existing billion-laughs security fixture, and confirmed empirically (no network activity during a real parse) that Python's non-validating expat parser never actually resolves `%PersDict;`'s external content regardless.
  - Raw extracted entry text also had its original XML indentation preserved verbatim as embedded whitespace runs; normalized to single spaces for clean prose when embedded in a rendered concept file.
  - Verified against the real dump directly (116,168 headwords) and end-to-end via the real pilot acceptance suite: `words/νόστος.md` and 464 other course-vocabulary word files now carry a genuine, correctly-formatted "Ancient Greek meaning" section citing real LSJ prose (e.g. νόστος: "νόστ-ος, ὁ ... return home, Hom. ... Il. 10.509", correctly citing Homer/Iliad). `data/lsj-cache/` populated with 636 real entries from that run. 1 of the 465 real files (`words/ὄϊς.md`) surfaced a third minor, known limitation: LSJ's own editorial bracket notation can incidentally produce a `[^...]`-shaped substring that collides with OKF markdown's footnote-reference syntax -- cosmetic, not a correctness issue (`okf.py`'s own footnote-definition logic only ever emits a definition for an id matching a real cited source, so this is an unresolved reference, never a duplicated/corrupted footnote); not fixed, see `references/sources/lsj.md` and a new comment in `okf.py` (the risk is general, not LSJ-specific) for why. 5 new tests against fixture data mirroring `CachedWiktextractIndex`'s own test shape (resolves from dump, persists across instances without the dump, caches confirmed absence, miss-without-dump is not cached, still rejects the billion-laughs payload); full suite (244 passed, 1 skipped) and ruff clean.
  - **Found and fixed via `/simplify`** (reuse/simplification/efficiency/altitude, 4 parallel agents): memoized the repeated `beta_code.beta_code_to_greek()` calls in `_load_entries()` -- the same short Beta Code fragments (case endings, particles, punctuation runs) recur constantly across ~728,000 total calls against the real dump; confirmed via `functools.lru_cache`'s own `cache_info()` that 268,624 of those (37%) were avoidable repeats, each otherwise re-paying the library's per-call overhead (it rebuilds its translation table and recompiles a regex every call, confirmed unfixed as of the latest PyPI release) for no reason. Also corrected this same docstring's `%PersDict` claim (see above) and simplified a single-use whitespace-collapsing regex to plain `str.split()`; both were reuse/simplification findings independent of the security one. No findings changed intended behavior or needed a follow-up.

- **Fixed `okf.write()` duplicating a concept's citation footnote when rewriting an existing file for an unrelated frontmatter-only change** (e.g. `pipeline.py`'s pruning step flipping `status` to `deprecated`) -- e.g. `read()`-ing a file, changing one field, and `write()`-ing it back would leave the same `[^id]: ...` footnote definition on disk twice. Root cause: `ConceptFile.body` can already end with a footnote-definitions block from a previous `render()` call (`read()` reconstructs `body` as everything after the frontmatter fence, footnotes included, by design), but `render()` unconditionally appended a freshly-computed footnote block on top without checking whether one was already there. First surfaced live this session when an under-scoped pipeline example accidentally pruned two real files (`grammar/aorist-3pl-osan.md`, `culture/cavafy.md`), both reverted at the time; this fix addresses the underlying mechanism, not just that one trigger. Fixed by stripping any existing footnote-definition lines from `body` before recomputing referenced ids and re-appending -- also self-heals a file already corrupted by this bug, if rewritten again. Verified: a real reproduction (write with a citation, `read()`, flip `status`, `write()` again) now shows the footnote exactly once, both before and after fixing; full suite (235 passed, 1 skipped) and the real integration pilot run unaffected.
- **Wired `sources.lsj` into `lexical_entry.build()`, closing the "Ancient-period sections have no meaning/definition text" gap** -- `LSJIndex.lookup()` was never called anywhere in `lexical_entry.py` (confirmed via grep before this fix), so Homeric/Attic sections only ever showed inflected forms, never a gloss, unlike the Modern period's Wiktextract-sourced sense text. Adds a single "Ancient Greek meaning" section, once per concept (not duplicated per period -- LSJ entries aren't period-scoped the way inflected forms are), whenever `periods` includes homeric and/or attic and `sources.lsj` has an entry for the lemma; independent of morphological attestation, matching how a Wiktextract gloss doesn't require attested forms either. An LSJ-only lemma (no eee_engine/Morpheus hit for either ancient period) still counts as attested in `extra_frontmatter["periods"]`, not just in the rendered body -- otherwise `pipeline.py`'s real candidate-acceptance gate (`if not concept.extra_frontmatter.get("periods"): ... discard`) would silently drop exactly the concepts this feature exists to help, LSJ content included. The once-per-lemma lookup is memoized via a separate `lsj_looked_up` flag, not `if lsj_entry is None:` -- `lookup()`'s legitimate "no entry" return value is also `None`, so that sentinel would re-query on every ancient period whenever nothing is found, the common case today. **Wiring only, not yet functional end-to-end**: `data/lsj/` is still an empty placeholder (`LSJIndex({})` everywhere it's constructed) -- the real 27 Perseus LSJ TEI-XML files (`references/sources/lsj.md`) haven't been downloaded, so this produces no visible output yet against real content; deliberately left for a separate follow-up rather than bundled here. 6 new tests against fixture data (entry found, no entry, not duplicated across both ancient periods, independent of attestation, lookup called once whether or not an entry is found); full suite (239 passed, 1 skipped) and the real integration pilot run unaffected (its `LSJIndex({})` is genuinely empty, so output is unchanged).

- **Gap-filler candidate resolution, pronoun, and budget-cache fixes** — found and fixed chasing the first real gated pilot runs (small real budgets against the OpenRouter-backed `GapFillerConfig`, `--run-paid-llm-tests`), each verified against real, paid API calls, not just unit tests.
  - `_read_vocabulary_candidates()` was misreading `translation_presence.tsv` (a per-lesson quiz answer key that coincidentally has its own `lemma` column) as vocabulary, feeding real quiz-answer lemmas into the pipeline as if they were course words. Now requires a `pos` column, not just `lemma`, before treating a TSV as vocabulary; `translation_presence.tsv` is explicitly skipped and logged quietly, not as a warning.
  - `collect_slot_forms()` was gap-filling every pronoun slot template against every plausible pronoun family (personal/demonstrative/relative/etc.) regardless of which family the lemma actually belongs to, burning real LLM requests on slots that can never apply to that lemma. Rewritten as a two-pass, family-aware lookup.
  - `pipeline.run()` used to re-attempt (and re-fail) every remaining candidate one-by-one after the gap-filler's `max_requests_per_run` budget was exhausted, and discarded the run's cache instead of preserving it. Now stops the run cleanly the moment the budget is hit, skips `grammar_rules`/`cultural_topics`/pruning (since the run never reached the rest of the course), and preserves the cache — verified twice, for real, that a small-budget run stops cleanly and a second real run against the same cache genuinely resumes instead of re-paying for already-resolved gaps.
  - `GapFillCache.make_key()` included the caller's `max_requests_per_run` in its cache key, meaning resuming an exhausted run with a *raised* budget (the whole point of that recovery path) silently invalidated every previously-cached gap instead of reusing it. Now normalizes the budget out of the key (memoized, since this ran on every `fill_gap()` call).
  - `RequestBudgetExceededError` (new, `okfbuild/sources/llm_gap_filler.py`) replaces a bare `RuntimeError` matched by exact message string for the budget-exceeded signal -- the old check would have silently stopped recognizing budget exhaustion the moment the message wording changed.
  - `NotLegalPronounException` (new, in the sibling `modern-greek-inflexion-eee` package -- see that package's own CHANGELOG, 2.1.10) replaces a bare `ValueError` that library used to raise for an Ancient-Greek-only pronoun (σύ, τίς, μιν, ὅδε, ...) run against the Modern Greek backend. `eee_engine.py`'s "not a modern Greek word" exception tuple now catches this by name instead of a broad, unrelated-bug-risking bare `ValueError`. This briefly meant a fresh `uv sync` installed a `modern-greek-inflexion-eee` without the new exception and `okfbuild.sources.eee_engine` failed to import -- flagged independently by an external Codex review of this same diff -- closed by bumping this repo's dependency floor to `>=2.1.10` once that release was actually live on PyPI.
  - README's Usage section rewritten with real, individually-verified-runnable examples (`SourceBundle` wiring, building one concept file, running the full pipeline over a course) and several gotchas found live while verifying them: `out_dir`'s pruning risk against this repo's own real content (`grammar/`/`culture/` files were accidentally marked `deprecated` once by an under-scoped example, reverted; the example now defaults to a scratch directory), `Path(...)` not expanding a leading `~` on its own, and what a healthy `report` actually looks like.

- **LLM gap-filler pipeline wiring** (5 sections, branch `feature/llm-gap-filler-pipeline-wiring`, not yet merged) — builds on the earlier `llm-backend-eee` foundation (`fill_gap()`/`GapFillCache`/`LLMModelConfig`, merged separately today) to make LLM-assisted morphology gap-filling actually usable end-to-end, from prompt context through a real pilot run to independent verification.
  - `fill_gap()` now receives a `context` string (the grammatical slot label, plus period/dialect/author/work when known) that reaches both the real LLM prompt — via `llm-backend-eee`'s own `label` mechanism, confirmed against its installed source — and the cache key, so a query under different context is never served from a differently-scoped cache hit. Course-level author/work/dialect metadata (curated in a new, deliberately small `okfbuild/course_context.py`, currently just the Odyssey and Kavafis Ithaki courses) is course-level signal ("this gap comes from the Odyssey course"), never conflated with word-level attestation ("Homer's own text uses this exact form").
  - `GapFillCache` gained `save()`/`load()`: atomic writes (temp file + `os.replace()`), a `format_version` field, exclusion of transient failures from persistence (an all-`CALL_FAILED` entry is never written as a stable negative result — it would wrongly block a legitimate retry), and run-ID-scoped resumability under a caller-supplied `gap_fill_cache_dir` (`<dir>/.gap_fill_runs/<run-id>/cache.json`). `pipeline.run()` shares one cache across every lemma it processes and automatically resumes the most recent incomplete run; a run that completes normally removes its own cache file.
  - A three-layer pytest gate protects any real, billed LLM API test from running by accident: a `paid_llm_api` marker, a `--run-paid-llm-tests` CLI flag (via a custom collection hook, not `addopts`, since `addopts` is trivially overridden by an explicit `-m` on the command line), and a fixture-level double-gate function (`require_paid_llm_gate()`) that re-checks a real API key plus `GREEK_KNOWLEDGE_RUN_PAID_LLM_TESTS=1` every time, regardless of how a test was invoked — the fixture-level check is the actual enforcement boundary, not the marker.
  - A real, two-model `GapFillerConfig` via OpenRouter (`openai/gpt-4o-mini` + `anthropic/claude-3.5-haiku`, one API key: `GREEK_KNOWLEDGE_OPENROUTER_API_KEY`) plus `okfbuild/gap_filler_pilot.py`'s `run_gap_filler_pilot()`: writes to an isolated, gitignored `build/gap-filler-pilot/` directory — never the tracked `words/`/`grammar`/`culture` trees, since an exploratory LLM-gap-filled run shouldn't land in already-reviewed output before a human sees it — plus a JSON "handoff" file recording every individual LLM-inferred form with full structured provenance (lemma/form/slot label/features/pos/language/period/method). Confirmed directly (OpenRouter's own API reference, plus the installed `llm-backend-eee` v0.2.1 source) that a routing provider can silently substitute a different model than requested, and that `llm-backend-eee` discards the response field that would reveal it — so the handoff's `method` field reflects the model *requested*, never confirmed as the one that actually responded. Documented, not fixed (would need a change in that separate package).
  - `okfbuild/morpheus_crosscheck.py`: a standalone tool cross-checking the handoff file's forms against the real Perseids Morpheus service, classifying each into `CONFIRMED` / `DIFFERENT_ANALYSIS` / `UNDERSPECIFIED` / `UNCONFIRMED` / `QUERY_FAILED` via a 7-axis UD-FEATS↔Morpheus vocabulary mapping built from real captured Morpheus responses (full, spelled-out English words like `"genitive"`) — not the abbreviated shape (`"gen"`) this repo's own pre-existing `MorpheusClient` test fixtures happen to use, which would have made the classifier look correct in tests while being silently wrong against every real response. Voice is modeled as match-sets, not a flat lookup: a `mediopassive` reading neither confirms nor contradicts a specifically-requested `Mid`/`Pass`. Purely informational — flags disagreement, blocks nothing, never modifies `words/*.md`.
  - Not yet done: the branch hasn't been merged; the real gated pilot has never actually been run (needs a real API key); no cross-check report exists yet against real output.
  - 215 tests in the suite as of this branch's tip (214 passing, 1 correctly skipped — the real gated pilot test), most of them new across these 5 sections. `ruff check` clean aside from one deliberately-unsuppressed `BLE001` (an intentional broad `except Exception:` converting any Morpheus/JSON/network failure into a documented sentinel, matching an existing pattern already used elsewhere in this codebase).
